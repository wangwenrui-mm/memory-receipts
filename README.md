# 小鲨 · 长期陪伴型 AI 记忆系统

一个跑在自己电脑上的**长期对话智能体**。

重点不在"会聊天"，而在**记得住、说得清出处、错了能改**。

支持四种接入方式（控制台 / 网页 / QQ / 科研版工具），核心逻辑完全相同，任选其一即可跑。

## 它解决什么问题

长期运行的对话智能体会出现三类**静默错误**——系统不报错，但结论是错的：

| 错误 | 表现 | 为什么常规指标发现不了 |
| --- | --- | --- |
| **无中生有** | 编造一条从未发生的事，并写进记忆 | 回答"看起来很相关" |
| **自我污染** | 拿自己先前的话当证据，互相佐证 | 召回率/准确率都测不出循环论证 |
| **陈旧失效** | 引用一条已被后续论文/实验推翻的数据 | 匹配成功即算命中，不看时效 |

对应设计见[核心设计](#核心设计三个反直觉的点)与 [docs/架构说明.md](docs/架构说明.md)。

## 五分钟上手（不需要 QQ）

```bash
# 1. 装依赖（唯一的硬依赖）
pip install websockets

# 2. 配置
copy config.example.json config.json
#    编辑 config.json：至少填 deepseek_key

# 3. 先用假模型试一遍（不花钱、不联网）
python chat_console.py --mock

# 4. 换成真模型（会计费，约 ¥0.002–0.006/轮）
python chat_console.py
```

看到 `你>` 就可以说话。`/quit` 退出。

**没有 Key 也能先看效果**：`--mock` 模式不会调用任何 API。

## 四种使用方式

| 方式 | 命令 | 适合 | 需要 QQ | 能主动找你 |
| --- | --- | --- | --- | --- |
| **控制台** | `python chat_console.py` | 调试、本机聊天 | ❌ | ❌ |
| **网页** | `python chat_web.py` | 手机连同一 Wi-Fi | ❌ | ❌ |
| **QQ** | `python run.py` | 手机随时收到 | ✅ | ✅ |
| **科研版** | `cd lab && python src/verify.py` | 核验论文数值 | ❌ | — |

### 1. 控制台（最推荐先试）

```bash
python chat_console.py --mock     # 假模型：不联网、不花钱、不改人格
python chat_console.py            # 真模型
python chat_console.py --dir ./sandbox   # 用独立数据目录，不碰正式数据
```

命令：`/reset` 清空对话、`/cost` 看花费、`/quit` 退出。

**价值**：改完代码立刻能试，不用重启 NapCat、不用扫码；`--mock` 零成本。

### 2. 网页（手机也能用）

```bash
python chat_web.py                 # http://127.0.0.1:8765
python chat_web.py --port 9000     # 换端口
python chat_web.py --lan           # 允许局域网访问（手机可连）
```

**手机用法**：电脑跑 `--lan` → `ipconfig` 查 IPv4 → 手机连同一 Wi-Fi → 浏览器打开 `http://电脑IP:8765`。

**安全**：默认只监听 `127.0.0.1`；`--lan` 时同网段的人都能访问，只在私人网络用。

### 3. QQ（要"她主动找你"才需要）

前置：QQ 小号（**不要用主号**）+ [NapCatQQ](https://github.com/NapNeko/NapCatQQ)（自行安装，遵守其许可）+ API Key。

1. 安装 NapCat 并登录小号
2. 开启 OneBot11 正向 WebSocket，端口 `3001`
3. `python run.py`

**QQ 唯一不可替代的能力**：手机随时能聊、**主动消息**（每天 8–15 条）、24 小时在线。

**代价**：自动化操作 QQ 违反其服务条款，有封号风险。这也是为什么推荐先用前两种通道。

### 4. 科研版工具（独立功能）

`lab/` 是一个独立的数值核验工具，跟聊天无关，可以单独拷出去用：

```bash
cd lab
python src/verify_doc.py 报告草稿.md data/records.jsonl  # 核验文档数值
python src/build_index.py data/corpus                    # 建论文索引
python src/search.py 温度                                # 查数据
python src/csv_to_jsonl.py 记录表.csv                     # Excel 转格式
python src/lint_records.py data/records.jsonl            # 检查记录规范
```

详见 [lab/README.md](lab/README.md)。

## 压力测试记录

发布前按"陌生人拿到这份东西"的标准做了三轮压测，**用的是系统 Python 3.11 + 真实 websockets 17.2**（不是内置运行时）。

### 首轮：25/27 —— 找到 2 个真问题

| 问题 | 现象 | 为什么必须修 |
| --- | --- | --- |
| **没填 API Key** | 直接抛 `RuntimeError: HTTP 401 Authentication Fails` + traceback | 新手会以为程序坏了 |
| **端口被占用** | 抛 `PermissionError: [WinError 10013]` + traceback | 网页通道起不来，看不出原因 |

### 修复

- 启动前检查 Key，给出三条出路（用假模型 / 填 Key / 换供应商），并附申请地址
- 端口占用时说明两种原因，并给出 `--port 8766` 的替代命令
- 运行时错误分类：401 → 查 Key；429 → 太频繁；402 → 余额不足；超时 → 查网络

### 同时修掉的 3 个隐蔽 bug

| # | 问题 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 第二句对话必崩 | 历史含孤立代理字符，`json.dumps` 写盘时 `UnicodeEncodeError` | `_dumps_safe()`：写盘前清非法字符 |
| 2 | 控制台刷 `找不到 adb` | 手机抓屏功能在找 adb | 通道内关闭 `screen.enable` |
| 3 | 假模型回显 prompt 导致编码错 | 回显了含非法字符的系统上下文 | 假模型只回固定文本 |

### 复测：27/27

| 压测项 | 结果 |
| --- | --- |
| 连续 100 轮 | 100 条全回复，**138 秒**，无退化 |
| 超长输入（8000 字） | 正常处理 |
| emoji / 引号 / 控制字符 | 不崩 |
| 全新解压 zip 后自检 | 13/13（快速模式） |
| 全新解压后直接对话 | 正常回复 |

### 兼容性修复

扫描发现 6 个文件使用了 Python 3.10+ 的联合类型语法（`int | None`），在 3.9 上会导入失败，而 README 声明的是 3.9+。已统一加 `from __future__ import annotations`，现在**真正支持 3.9**。

### 一个容易被忽略的泄漏

`__pycache__` 里的 `.pyc` 二进制**会嵌入源码的绝对路径**（如 `C:\Users\<用户名>\...`）。首次扫描命中 6 处，清掉缓存后归零。`.gitignore` 已忽略，但提交前值得确认。

## 核心设计（三个反直觉的点）

### 1. 证据里排除"它自己说过的话"

做核验时，证据集合**不含智能体自己生成的回复、摘要、日记**。

**原因**：智能体会说"这是我编的""我记岔了"。把这些纳入证据，判定器就会用"她自己否认过"去证明"事实不存在"，形成循环论证，把**真实记忆误判成虚构**。

实测（300 轮连续对话）：

| 条件 | 准确率 | 误报率 |
| --- | --- | --- |
| 排除自指证据 | 88.3% | **6.7%** |
| 允许自指证据 | 85.0% | 13.3% |

**误报率减半，且结论反直觉。**

### 2. 只标记，不改写

判为"无依据"的陈述：**不删除、不改写**任何原始记录，只在装配上下文时附加否定标记。

```
原始：他昨晚很生气（事实）
标记：他昨晚很生气【已被否定的主张】
```

原始证据始终可审计——删和改都会破坏可追溯性。

### 3. 宁可说"未溯源"，也不猜

判定结果只有五种：

| 结果 | 含义 |
| --- | --- |
| 有依据 | 证据里能找到匹配记录（附来源与日期） |
| 已过时 | 记录存在，但已被更晚的结果覆盖（附新值） |
| 矛盾 | 记录存在，数值对不上 |
| 未溯源 | 没有该记录，或单位不在词表 |
| 计划 | 识别为规划/目标，不做核验 |

`未溯源` 是刻意保留的：抽不到就说抽不到。

**时效判定是保守的**：只有当"同参数 + 同样本 + 更晚日期"或显式 `superseded_by` 时，才把旧值判为"已过时"。未声明样本的记录一律视为有效——不同批次的实验数据都可能是真的，不能仅凭日期就把真实数据判死。

## 安全与隔离

| 措施 | 说明 |
| --- | --- |
| 只用私聊 | 群聊在代码层禁用 |
| 本地存储 | 所有记忆在 `data/`，不上传 |
| Key 管理 | 只在 `config.json`，不入库、不进仓库 |
| 紧急停止 | 项目根目录放一个 `PAUSE` 空文件，立即停止收发 |
| 通道可选 | 不用 QQ 就没有封号风险 |

**建议**：用小号；不要用主号；网页 `--lan` 只在私人网络开。

## 已知限制

| 限制 | 说明 |
| --- | --- |
| 单位词表封闭 | 约 70 项，表外单位一律"未溯源" |
| 不做单位换算 | 850 ℃ 与 1123 K 视为不可比 |
| 精确相等 | 无容差，849.9 与 850 判为不一致 |
| 参数名需一致 | 命名不统一会导致大量"未溯源"（最大实践风险） |
| 不建模否定语义 | "没测到 850 ℃" 无法与 "850 ℃ 有记录" 区分 |
| 时效判定需显式声明 | 未声明 `scope` 时不做新旧判定 |
| 抽取只认"数字+单位" | 纯文字描述（"高温退火"）抓不到 |

## 常见问题

**Q：报 `ModuleNotFoundError: No module named 'websockets'`**
A：`pip install websockets`。这是唯一的硬依赖。

**Q：没有 API Key 能试吗**
A：能。`python chat_console.py --mock`，不联网、不花钱。

**Q：报 `UnicodeEncodeError: surrogates not allowed`**
A：数据文件里有非法字节。运行 `python tools/repair_data.py --fix`。

**Q：报 `端口 8765 用不了`**
A：`python chat_web.py --port 8766`。也可能是上次的窗口没关干净。

**Q：连续聊很久会不会越来越慢**
A：不会。九层记忆都有硬上限，上下文恒定约 6k token。实测 100 轮稳定。

**Q：能不能不用 DeepSeek**
A：可以。改 `config.json` 的 `deepseek_base` 和 `model`（任何 OpenAI 兼容接口：通义、Kimi、本地 ollama）。

更多见 [docs/使用手册.md](docs/使用手册.md)。
