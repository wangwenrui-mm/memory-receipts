# 使用手册

四种用法，按"从易到难"排序。**建议先跑方式 1，确认环境通了再上 QQ。**

---

## 通用准备（四种方式都要）

### 1. 装 Python

需要 **Python 3.9 或以上**。

```bash
python --version
```

没有的话：https://www.python.org/downloads/ （安装时勾选 *Add Python to PATH*）

### 2. 装依赖

```bash
pip install -r requirements.txt
```

最少只需要 `websockets`（因为 `bridge.py` 在模块级导入它）。其余是可选的：

| 依赖 | 用途 | 不装的后果 |
| --- | --- | --- |
| `websockets` | QQ 通道 / 模块级导入 | **必须装** |
| `numpy` + `onnxruntime` + `tokenizers` | 向量检索（语义捞旧事） | 退化为关键词检索 |
| `edge-tts` | 语音回复 | 不能发语音 |

### 3. 配置文件

```bash
copy config.example.json config.json
```

必填两项：

```json
{
  "owner_qq": [你的QQ号],
  "deepseek_key": "sk-你的key"
}
```

其余保持默认即可（默认值都写在 `bridge.py` 的 `DEFAULT_CONFIG` 里，配置文件只是覆盖）。

### 4. 数据目录

首次运行会自动创建 `data/`，里面是：

```
data/persona.json     人格（心情/精力/六维/关系温度/日记）
data/history.json     对话历史（有 TTL）
data/memory.jsonl     长期记忆
data/archive.jsonl    归档
data/pins.jsonl       置顶
data/vec.db           向量索引（SQLite）
```

**备份就备份整个 `data/`**，换电脑拷过去即可。

## 方式 1：控制台通道（最推荐先试）

```bash
python chat_console.py --mock     # 假模型：不联网、不花钱、不改人格
python chat_console.py            # 真模型：会计费
```

看到 `你>` 后直接输入。命令：

| 命令 | 作用 |
| --- | --- |
| `/reset` | 清空当前对话记忆（人格和长期记忆不动） |
| `/cost` | 看最近 24 小时花费 |
| `/quit` | 退出 |

**它的作用**：

- 验证"人格 + 记忆 + 核验"整条链路是否正常
- 改完 `bridge.py` 立刻能试，不用重启 NapCat、不用扫码
- `--mock` 模式零成本，适合反复调试

**它不能做什么**：不能主动找你、关掉窗口就没了、手机上用不了。

## 方式 2：网页通道（手机也能用）

```bash
python chat_web.py                 # 打开 http://127.0.0.1:8765
python chat_web.py --port 9000     # 换端口
python chat_web.py --mock          # 假模型
python chat_web.py --lan           # 允许局域网访问（手机可连）
```

打开浏览器访问提示的地址即可。

**手机怎么用**：

1. 电脑上运行 `python chat_web.py --lan`
2. 查电脑内网 IP：`ipconfig`，找 `IPv4 地址`（形如 192.168.1.23）
3. 手机连**同一个 Wi-Fi**，浏览器打开 `http://192.168.1.23:8765`

**安全提示**：网页通道没有登录验证。

- 默认只监听 `127.0.0.1`，只有本机能访问
- `--lan` 时同网段的人都能访问——**只在私人网络用**，不要在学校/公司/咖啡厅的网络开
- 想更安全：在路由器上限制、或用手机热点组网

**它的作用**：比控制台好看，手机能用，且完全没有封号风险。

## 方式 3：QQ 通道（要"她主动找你"才需要）

### 前置条件

1. 一个 **QQ 小号**（强烈建议，不要用主号）
2. [NapCatQQ](https://github.com/NapNeko/NapCatQQ)（不随本仓库分发，请自行安装并遵守其许可）
3. 一个 DeepSeek API Key

### 步骤

1. 安装 NapCat，用你的小号登录
2. 在 NapCat 里开启 **OneBot11 正向 WebSocket**，端口设 `3001`
3. 确认 `config.json` 里 `napcat_ws` 是 `ws://127.0.0.1:3001`
4. 启动：

```bash
python run.py
```

`run.py` 会做三件事：检查/拉起 NapCat、连 WebSocket、守护 `bridge.py`。挂了会自动重连。

### 它能做别人做不到的事

| 能力 | 说明 |
| --- | --- |
| 手机随时能聊 | 用手机 QQ 就能找她 |
| **主动消息** | 每天 8–15 条，按她的心情和作息发 |
| 24 小时在线 | 电脑开着她就活着 |

**代价**：有封号风险。自动化操作 QQ 违反其服务条款，账号可能被限制——本项目作者就遇到过。

### 出问题怎么办

| 现象 | 处理 |
| --- | --- |
| 不回消息 | 看 `logs/` 最新日志；确认 QQ 还在线 |
| 提示连不上 WS | NapCat 没起、或端口不是 3001 |
| 卡住不动 | 停掉所有 python 进程再重开（`停止全部.bat`） |
| 要临时停止 | 在项目根目录建一个 `PAUSE` 文件（空文件即可） |

## 方式 4：科研版工具（独立功能，不聊天）

`lab/` 是一个**独立**的数据核验工具，跟聊天无关，也可以单独拷出去用。

```bash
cd lab

# 核验一份文档里的数值能不能在实验记录里找到出处
python src/verify_doc.py 报告草稿.md data/records.jsonl

# 按关键词查论文里的数据
python src/build_index.py data/corpus
python src/search.py 温度

# 把 Excel/CSV 记录转成系统格式
python src/csv_to_jsonl.py 记录表.csv

# 检查记录是否合规
python src/lint_records.py data/records.jsonl
```

详见 [lab/README.md](lab/README.md)。

## 假模型模式（省钱调试）

`chat_console.py` 和 `chat_web.py` 都支持 `--mock`：

- 不调用任何 API，**零花费**
- 不修改人格、不写长期记忆（只有历史记录会动）
- 回一句固定的"链路是通的"

**用途**：验证配置、试新功能、给别人演示时不烧钱。

## 常见问题

**Q：报 `ModuleNotFoundError: No module named 'websockets'`**
A：`pip install websockets`。这是唯一的硬依赖。

**Q：报 `UnicodeEncodeError: surrogates not allowed`**
A：数据文件里有非法字节（多半是从别处导入的历史数据）。运行：

```bash
python tools/repair_data.py --fix
```

**Q：控制台里中文是乱码**
A：Windows 控制台编码问题。先执行 `chcp 65001`，或用 Windows Terminal。代码里已做编码保护，多数情况不会出现。

**Q：她说话很短/很怪**
A：人格参数在 `data/persona.json` 里（六维：黏人、毒舌、话量、独立、敏感、主动）。也可以改 `config.json` 的 `system_prompt`。

**Q：怎么让她忘掉某件事**
A：`data/` 是纯文本，可以手工编辑：
- `memory.jsonl` 长期记忆
- `pins.jsonl` 置顶
- `persona.json` 里的 `diary` 数组

改之前先备份 `data/`。

**Q：能不能不用 DeepSeek**
A：可以，只要接口兼容 OpenAI 格式。改 `config.json` 的 `deepseek_base` 和 `model` 即可（通义、Kimi、本地 ollama 都行）。

**Q：要不要花钱**
A：一次对话约 ¥0.002–0.006（取决于长度）。日记约 ¥0.004。用 `--mock` 或 `/cost` 可以控制。
**Q：跑起来一堆红字，是不是坏了**
A：先跑出厂自检，它会告诉你哪里不对：

```
python tools/selftest.py
```

**Q：报 HTTP 401 Authentication Fails**
A：API Key 不对。检查 config.json 的 deepseek_key 是不是完整（sk- 开头，没有多余空格）。

**Q：报 端口 8765 用不了 / WinError 10013**
A：换个端口：python chat_web.py --port 8766。也可能是上次的窗口没关干净。

**Q：连续聊很久会不会越来越慢**
A：不会。九层记忆都有硬上限，上下文恒定在约 6k token。实测连续 100 轮耗时稳定。
